# ブラウザ・端末の制約

2アプリに共通する技術的な前提をまとめる。
ここに書いた対応状況は2026年10月時点の見込みであり、実装前に必ず実機で確かめる。

## 1. カメラ

| 項目 | 内容 | 状態 |
|---|---|---|
| 映像の取得 | `getUserMedia` で取得する。HTTPS が必須。 | 【提案】 |
| 露出・シャッター速度の手動設定 | 一部の Android（Chrome）では `applyConstraints` で設定できる。iOS のブラウザでは難しい見込み。 | 【要検証】 |
| フレームごとの時刻 | `requestVideoFrameCallback` で取得できる見込み。等速回転の周期の測定などに使う。 | 【要検証】 |
| 自動処理 | 自動露出、自動ホワイトバランス、手ぶれ補正、HDR（階調の自動調整）が測光や形状に影響する。 | 【要検証】 |
| 画素値の非線形性 | 画素値は光量に比例しない（ガンマ補正）。測光では逆補正が要る。 | 【提案】 |
| レンズの自動切替 | 近距離で超広角やマクロに自動で切り替わる機種がある。測定領域がずれる原因になる。 | 【要検証】 |

露出を制御できない端末への対策として、偏光ラボでは同じ画像内の非偏光の基準領域との比を取る。

## 2. 動画ファイル

| 項目 | 内容 | 状態 |
|---|---|---|
| 読み込み | `<video>` で再生し、Canvas に描いて画素を読む。 | 【提案】 |
| 形式 | iPhone の MOV（HEVC）やスローモーション動画が再生できるかは、端末とブラウザに依存する。 | 【要検証】 |
| フレームレート | アプリが扱うのは撮影時の値ではなく、ファイルの再生フレームレートである。スロー撮影の動画では実時間との換算が要る。 | 【提案】 |
| コマ送り | `currentTime` の指定によるコマ送りは、ずれや取りこぼしが起こりうる。 | 【要検証】 |

## 3. センサー

| 項目 | 内容 | 状態 |
|---|---|---|
| 姿勢・角速度 | `DeviceOrientation` / `DeviceMotion` で取得する。HTTPS が必須。 | 【提案】 |
| iOS の許可 | ユーザーの操作（ボタンのタップ）を起点に許可を求める必要がある。 | 【提案】 |
| 方位角 | OS が角速度を積分した角度を返す。短時間なら実用になる見込み。 | 【要検証】 |
| 磁気（コンパス） | 机のスチールや磁石で数度以上狂う。角度の測定には使わない。 | 【提案】 |
