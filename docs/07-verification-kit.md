# 検証キット

装置が成立するかを実物で確かめるための道具。アプリ本体の前に作る（`../README.md` の6節）。
全体が【提案】。使ってみて書き換える。

## 1. 構成

| ファイル | 内容 | 関係する要件 |
|---|---|---|
| `index.html` | 入口 | |
| `kit/light.html` | 光源ページ。回転台に載せるスマホで開く。 | POL-F-60〜65 |
| `kit/record.html` | 記録ページ。上から見下ろすスマホで開く。 | POL-F-01・02・05・07・08・09・41 |
| `tools/analyze.py` | 記録の解析。パソコンで動かす。 | POL-Q-01・03・21・22 |
| `tools/turntable.py` | phyphox のジャイロの記録から、回転台の速さとむらを求める。 | POL-Q-03 |

- ビルドの要らない単一のHTMLファイルで書いた。本体の技術構成（POL-Q-14）を決めたものではない。
- カメラを使うので、HTTPS で開く。GitHub Pages で公開すれば、`https://shin-phys.github.io/polarization-lab/` が入口になる（リポジトリの Settings → Pages で main ブランチのルートを公開する）。
- 映像は端末の外へ送らない（POL-N-01）。

## 2. 光源ページ

- 色（白・赤・緑・青）と、表示の明るさ（灰色の濃さ）を選んで「表示を始める」を押す。
- 全画面、画面の向きの固定、画面の自動消灯の停止を試みる。できなかったものは画面に出す。
- 表示中に画面をタップすると、設定が出る。
- 中心の十字は、回転中心と穴の位置合わせに使い、測定中は消す。
- 端末の画面の明るさは最大付近にし、自動調整・True Tone・Night Shift を切る（POL-F-62・65）。
- iPhone の Safari は全画面にならない。「ホーム画面に追加」して開くと、時計などの表示が減る。

## 3. 記録ページ

### 操作

1. カメラを選んで「カメラを開始」。レンズの自動切替を避けるには、一覧から使うカメラを指定する（POL-N-06）。
2. 「露出・ピント・色を固定」を押す。結果は「○」「×」「非対応」で出る。固定できない端末でも記録はできる。
3. 役割（基準・偏光（穴）・ブランク・試料）を選んで「枠を追加」。映像の上でドラッグして動かし、「大きさ」で半径を変える。
4. メモに条件を書き、「記録開始」。自動で止める時間を選べる。
5. 「CSVを保存」。必要なら「画像を保存」で枠の位置も残す。

- 枠の位置と設定は、次に開いたときも残る。
- 狭い画面では、映像が画面の上に固定される。
- 「1. 映像」で「動画ファイル」を選ぶと、撮影済みの動画を読み込んで記録できる（POL-F-42）。動画は最後まで記録する。iPhone の標準カメラで AE/AF ロックをかけて撮れば、露出を固定した記録になる（5.2節）。
- 白飛び（画素の1%超が250以上）と暗すぎを画面に出す。白飛びのときは、光源ページの「表示の明るさ」を下げる。
- フレームごとの時刻は `requestVideoFrameCallback` で取る。取りこぼしたコマ数を出す（処理幅を下げると減る）。

### CSV の形式

先頭の `#` で始まる行が条件の記録、その次が列名、以降が1コマ1行。

| 列 | 内容 |
|---|---|
| `frame` | 記録開始からのコマ番号 |
| `t_ms` | 撮影時刻（記録開始が0、ミリ秒）。取れないブラウザでは描画のタイミング。 |
| `media_time`、`presented_frames` | ブラウザが返す値（取りこぼしの確認用） |
| `proc_ms` | 処理した時刻 |
| `<枠>_R`、`_G`、`_B` | 枠の中の画素値の平均（0〜255）。ガンマ補正前、比を取る前。 |
| `<枠>_sat` | 枠の中で白飛びした画素の割合 |

枠の名前は、基準が `ref1`、偏光の穴が `hole1`、ブランクが `blank1`、試料が `s1`、`s2`…。条件の行には、メモ、端末、カメラの設定値、固定の結果、枠の位置と画素数が入る。

## 4. 解析スクリプト

```
python tools/analyze.py 記録.csv            # G で解析
python tools/analyze.py 記録.csv --ch all   # R・G・B それぞれ
python tools/analyze.py 記録.csv --plot     # 波形とリサージュ図形を PNG で保存
python tools/analyze.py --demo              # 答えの分かっている模擬データで試す
```

numpy が要る（図には matplotlib）。出すものは次のとおり。

| 項目 | 内容 | 関係 |
|---|---|---|
| コマの間隔 | 平均 fps、間隔が空いた所の数 | |
| 回転むら | 90° ごとの所要時間と、等速回転からのずれ（ガンマ2.2で戻した波形の交差から求める目安） | POL-Q-03 |
| 変動の深さ m | 各枠の「1回転に2回」の成分の振幅 ÷ 平均 | |
| p/m | 基準の変動の深さ ÷ 位相の基準の枠の変動の深さ | POL-Q-01 |
| 旋光角 | 推定法 A（当てはめ）と B（符号付き面積）を、補正なし・ガンマ2.2・基準との比の3通りで | POL-Q-21・22 |

- 位相の基準は `blank1`、なければ `hole1`。`--base` で変えられる。
- 解析には、記録の中で整数回転ぶんだけを使う（POL-F-38）。
- 推定法 C（角度軸の成分）は、印の検出を入れてから加える。

## 5. 確かめること

### 5.1 回転台（POL-Q-03）

- phyphox の「ジャイロスコープ」で、光源にするスマホを回転台の中央に載せて記録する。3回転以上（目安60秒）。
- 書き出した zip を `python tools/turntable.py 記録.zip --plot` にかける。平均の周期、角速度の範囲、90° ごとの所要時間、等速回転からのずれ、細かい振動を出す。2回転以上あれば、むらが毎回同じ角度で起こるか（相関）も出す。
- 記録ページでも、`blank1` か `hole1` の記録から回転むらの目安が出る。

#### 実測（2026-10-13、キャンドゥ ソーラー式回転台、iPhone、1.2回転）

| 項目 | 値 |
|---|---|
| 平均の周期 | 17.7 秒（3.4 rpm） |
| 角速度（0.5秒平均） | 0.23〜0.55 rad/s（最大÷最小 2.4） |
| 90° ごとの所要時間 | 5.3、5.5、3.5、3.3 秒 |
| 等速回転からのずれ | 最大 約24° |
| 細かい振動 | 約2.6 Hz、角度の振れ ±0.4° |

- 速さは1回転の中でゆっくり変わる（半回転ごとに遅い・速いが入れ替わる形）。1.2回転しかないので、毎回同じ角度で起こるか（載せた荷重の偏りや台の傾きによるものか）は、まだ判断できない。
- 角度を等速回転の周期で換算する方式（POL-F-12）は、このままでは使えない（角度で最大 約24°ずれる）。マリュスの法則の角度は画像内の印で取る（POL-F-11）。
- 旋光の同時測定への影響を、この実測の回転を当てはめた模擬データで見積もった（真の値 5・10・20°、露出固定、60秒）。

| 推定法 | 補正なし | ガンマ2.2 |
|---|---|---|
| A（当てはめ） | 5.12・10.31・20.78° | 4.95・9.92・19.93° |
| B（符号付き面積） | 5.06・9.89・18.26° | 4.96・9.91・19.90° |

  ブランクと試料は同じ回転を見ているので、ガンマを戻せば A・B とも 0.1° 以内に収まった。補正なしの A は、むらがあると誤差が増える（等速なら 20.02°）。この回転台でも、同時測定には使える見込み。
- 次に確かめること：3回転以上の記録。スマホの向きを180°変えて載せ直したとき、遅い角度がスマホについて動くか（荷重の偏り）、台に残るか（台の癖）。電池を替えたとき、ソーラーだけのときの速さ。

### 5.2 基準の紙（POL-Q-01）

- 構成B（マリュスの法則の配置）で、`ref1`（紙）と `hole1`（穴）を置き、2回転以上記録する。
- 露出を固定した記録で判断する。iPhone なら、標準カメラで AE/AF ロックをかけて撮った動画を記録ページで読み込む。自動露出のままだと、全体の明るさの変動が基準にも乗り、p/m が大きく出る（模擬データでは、真の値4%に対して約18%と出た）。
- 露出を固定できない端末しかない場合は、固定できる端末を借りて紙だけを確かめる。
- 紙の枚数（1枚・2枚・3枚）を変えて比べる。

### 5.3 推定法と比の取り方（POL-Q-21・22）

- 構成Bの旋光の配置で、全部の容器に水を入れた記録（ゼロ点）と、試料を入れた記録を取る。
- 解析結果の表で、A と B、補正なし・ガンマ2.2・比の差を見る。
- 模擬データでの見通し（`--demo`）
  - 理想条件（等速、漏れなし、露出固定）では、A は補正の有無によらず真の値を返した。B は補正なしで小さめ（真の値20°に対し18.3°）、ガンマ2.2で補正すると真の値に一致した。
  - 自動露出が働くと、比を取らない値は1割以上大きく出た。比を取ると真の値に近づいた。
- 実物でも同じ傾向か、ゼロ点を差し引くとどこまでそろうかを確かめる。

## 6. 開発時の確認

ヘッドレスの Chromium に、cos² で明るさが変わる円を描いた疑似映像（旋光角12°相当）をカメラとして入力し、記録から解析まで通した。推定法 A で 11.9〜12.0° を得た。実機（iPhone・Android）での確認はこれから。
